# Contributing

Contributions that help other frontend developers learn are welcome: clearer explanations, corrections, meaningful tests, and well-scoped exercises.

1. Check the existing folders and [machine-coding index](machine-coding/README.md) before adding material. Open an issue for a large change or a new tooling dependency so its scope can be discussed.
2. Keep examples understandable and runnable. Explain important state, data flow, edge cases, accessibility choices, and trade-offs where they apply. Avoid abstractions that do not help the exercise.
3. Add tests when they protect meaningful behavior, especially tricky interactions or asynchronous cases. State how to run or manually verify the example.
4. Use descriptive titles and links. If you change a path, update references to it. Keep each pull request focused and explain what changed and how you checked it.
5. Share only material you have the right to publish. Do not submit copied proprietary interview questions, confidential feedback, personal scores, or private preparation notes.

For machine-coding submissions, use the [approach guide](machine-coding/README.md) as a guide to the reasoning. An exercise README should describe the actual implementation accurately and distinguish present behavior from possible follow-up requirements. React is useful for many components; use browser APIs directly when those APIs are the subject of the exercise.
